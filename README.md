# Домашнее задание №3. Docker. Bash

## Описание проекта

В репозитории реализованы два компонента:

- **generator** — генератор CSV-данных.
- **reporter** — аналитик данных, который читает CSV и формирует HTML-отчёт.

Оба компонента запускаются в отдельных Docker-контейнерах, но работают с файлами, которые хранятся локально на хосте в папке `data/`. Это реализовано через монтирование директории хоста внутрь контейнера (bind mount), поэтому созданные `data.csv` и `report.html` остаются в проекте даже после завершения контейнера.

## Структура проекта

```text                     
tp-hw-3/                    # Корневая папка проекта
|-- data/                   # Папка с результатами работы контейнеров (data.csv, report.html)
|-- generator/              # Модуль генерации данных
|   |-- .dockerignore       # Файлы и папки, которые не попадают в контекст сборки Docker
|   |-- Dockerfile          # Dockerfile для генератора CSV-данных
|   |-- generate.py         # Python-скрипт, который создаёт файл data.csv
|-- local_data/             # Папка для локальной отладки генератора без Docker
|-- reporter/               # Модуль анализа данных и построения отчёта
|   |-- .dockerignore       # Файлы и папки, которые не попадают в контекст сборки Docker
|   |-- Dockerfile          # Dockerfile для аналитика
|   |-- package.json        # Описание зависимостей и скриптов аналитика
|   |-- report.js           # Скрипт для чтения CSV и генерации HTML-отчёта
|-- .gitignore              # Файлы и папки, которые Git не должен отслеживать
|-- README.md               # Инструкция по запуску и структуре проекта
|-- run.sh                  # Основной bash-скрипт управления проектом
```

## Команды

### Генератор данных

```bash
./run.sh build_generator
./run.sh run_generator
./run.sh create_local_data
```

- `build_generator` — собирает Docker-образ для контейнера генератора.
- `run_generator` — запускает контейнер генератора, который сгенерирует `data/data.csv` локально.
- `create_local_data` — создаёт `local_data/data.csv` для локальной отладки без Docker.

### Аналитик данных

```bash
./run.sh build_reporter
./run.sh run_reporter
```

- `build_reporter` — собирает Docker-образ для контейнера аналитика.
- `run_reporter` — запускает контейнер аналитика, который сгенерирует `data/report.html` локально.

### Вспомогательные команды

```bash
./run.sh structure
./run.sh clear_data
./run.sh inside_generator
./run.sh inside_reporter
./run.sh report_server
```

- `structure` — выводит структуру проекта, исключая служебное содержимое.
- `clear_data` — удаляет из папки `data/` все сгенерированные `.csv` и `.html`.
- `inside_generator` — показывает содержимое директории `/data` изнутри контейнера генератора.
- `inside_reporter` — показывает содержимое директории `/data` изнутри контейнера аналитика.
- `report_server` — запускает отдельный контейнер `nginx:alpine`, который раздаёт HTML-отчёт через веб-сервер.

## Как воспроизвести результат

### 1. Сборка образов

```bash
./run.sh build_generator
./run.sh build_reporter
```

### 2. Генерация данных и отчёта

```bash
./run.sh run_generator
./run.sh run_reporter
```

После этого в папке `data/` должны появиться:

- `data.csv`
- `report.html`

### 3. Проверка содержимого папки `data/` из контейнеров

```bash
./run.sh inside_generator
./run.sh inside_reporter
```

Внутри контейнеров будут видны те же файлы, что лежат локально в папке `data/`.

### 4. Очистка сгенерированных файлов

```bash
./run.sh clear_data
```

После выполнения команды в папке `data/` удалятся `.csv` и `.html` файлы.

## Как открыть HTML-отчёт локально

После создания отчёта (пункт 2) требуется запустить веб-сервер:

```bash
./run.sh report_server
```

Команда запускает контейнер на образе `nginx:alpine`, публикует порт `8080` хоста на порт `80` контейнера и монтирует папку `data/` в стандартную директорию статических файлов Nginx — `/usr/share/nginx/html`.

После этого отчёт будет доступен по адресу:

```text
http://localhost:8080/report.html
```

Проверить работу сервера можно командами:

```bash
docker ps
docker port hw3-report-server
curl http://localhost:8080/report.html
```

Если последняя команда возвращает HTML-код страницы, значит сервер работает корректно.

### Как остановить сервер

Чтобы остановить веб-сервер, выполните команду:

```bash
docker stop hw3-report-server
```

После остановки контейнер перестанет обслуживать запросы, и страница больше не будет открываться.

## Как открыть отчёт в GitHub Codespaces

### Порядок действий

1. Открыть репозиторий в GitHub Codespaces.
2. Выполнить:

```bash
./run.sh build_generator
./run.sh run_generator
./run.sh build_reporter
./run.sh run_reporter
./run.sh report_server
```

3. Открыть вкладку **Ports**/**Порты** в интерфейсе Codespaces.
4. Найти порт `8080`.
5. Нажать **open in browser**/**открыть в браузере**.
6. В открытой ссылке дописать путь `/report.html`.

<details>
<summary><b>Как открыть отчёт без /report.html</b></summary>

Если нужно, чтобы отчёт открывался сразу по корневой ссылке, выполните команду:

```bash
cp data/report.html data/index.html
```

Эта команда создаст файл `data/index.html` на основе `data/report.html`. После этого отчёт будет открываться по корневой ссылке без необходимости вручную дописывать путь `/report.html`.

P.S. При использовании команды `clear_data` файл `index.html` также будет удалён.

</details>

GitHub Codespaces использует переадресацию портов: веб-сервер работает внутри Docker-контейнера, контейнер работает на хосте Codespaces, а доступ с компьютера проверяющего идёт через forwarded port, который Codespaces делает доступным в браузере.

## Как устроено решение

- Генератор и аналитик запускаются в отдельных контейнерах.
- Данные не хранятся внутри контейнеров постоянно, а записываются в локальную папку `data/` на хосте.
- Для доступа к локальным файлам используется bind mount.
- Для публикации HTML-отчёта используется третий контейнер на образе `nginx:alpine`.
- Доступ к отчёту обеспечивается через проброс порта `8080:80`.
